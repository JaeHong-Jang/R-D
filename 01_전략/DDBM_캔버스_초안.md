# DDBM 캔버스 초안 — 인공지능 활용 온라인 정보 분석 및 검증 서비스

> 각 블록은 실습 자료 서식(요지 1~2문장 → 빈 줄 → `- **항목명**: 설명`)에 맞춰 바로 붙여 넣을 수 있게 썼다.
> 앞판 5블록(개요·미션·가치제안·혜택·핵심활동)은 팀의 의도를 담는 칸이라 팀원들이 읽고 고쳐 쓴 뒤 저장할 것.
> 숫자는 모두 출처(맨 아래 참고자료 번호)가 있거나 우리 팀이 정한 목표치다.

---

## 개요

일반 독자가 포털·SNS에서 본 뉴스 기사나 게시글의 URL(또는 본문)을 넣으면, 생성형 AI가 제목이 본문과 맞는지, 글 속 핵심 주장마다 뒷받침하거나 반박하는 근거가 있는지를 찾아 출처 링크와 함께 보여준다. AI가 판단하기 어려운 주장은 검토자(팩트체커)가 확인한 뒤 판정을 확정한다.

- **하위주제**: 뉴스·SNS 주장 사실확인 보조 (+ 낚시성 제목 탐지)
- **누가**: 뉴스를 읽고 공유하는 일반 독자 / 판정을 확인하는 검토자
- **무엇을**: 기사 속 주장별 판정과 근거·출처
- **왜**: 생성형 AI가 만든 허위정보는 사람도, 기존 탐지기도 구별하기 더 어렵다 [8]

## 미션(MISSION)

기사 한 건을 넣으면 1분 안에, 핵심 주장마다 판정과 서로 다른 출처 2개 이상의 근거를 함께 보여준다. 근거를 찾지 못한 주장은 판정하지 않고 '근거 부족'으로 표시한다.

- **응답 시간**: 기사 1건당 1분 이내 (AVeriTeC 2025 공유과제가 주장당 1분 제한을 둔 것을 참고 [5])
- **근거 기준**: 판정 하나에 출처 2개 이상, 출처 원문에서 가져온 인용 문장 포함
- **판단 보류**: 근거가 부족하거나 근거끼리 충돌하면 판정 대신 '근거 부족/논쟁 중'으로 표시하고 검토 대기열로 보냄

## 가치제안(VALUE PROPOSITION)

뉴스를 읽는 일반 독자에게 "이 기사 믿어도 되나?"라는 질문의 답을 점수 하나가 아니라 주장별 근거와 출처로 보여준다. 독자는 결론을 그대로 받아들이지 않고 출처를 직접 열어 확인할 수 있다.

- **주장별 판정 리포트**: 기사에서 확인 가능한 주장을 뽑아 '사실 / 사실 아님 / 근거 부족 / 논쟁 중'으로 표시
- **근거·출처 카드**: 판정마다 출처 원문 인용, 링크, 발행일
- **제목-본문 일치 점검**: 제목이 본문 내용보다 과장되거나 본문과 다른지 표시(낚시성 제목)
- **기존 팩트체크 연결**: 같은 주장을 이미 검증한 팩트체크 기사가 있으면 먼저 보여줌
- **검토 여부 표시**: 사람이 확인한 판정과 AI만 낸 판정을 구분해서 보여줌

## 혜택(BENEFITS)

일반 독자는 공유하기 전에 근거를 확인할 수 있고, 검토자는 근거 수집 시간을 줄여 판정에 집중하며, 운영 기관은 검토 이력이 쌓인 판정 DB를 얻는다.

- **일반 독자**: 기사를 공유하기 전 주장별 근거를 확인, 출처를 직접 열어볼 수 있음
- **검토자(팩트체커·기자·교사)**: AI가 주장 추출과 근거 수집 초안을 만들어 주므로 확인과 판정에 시간을 씀
- **운영 기관(언론사·포털·교육기관)**: 검토를 거친 판정이 쌓여 같은 주장이 다시 들어오면 재사용, 판정 근거 기록으로 AI 기본법의 투명성 요구에 대응 [12]
- **사회**: 허위정보가 퍼지기 전 단계에서 출처를 확인하는 습관

## 핵심 활동(KEY ACTIVITIES)

시스템은 주장 추출, 근거 수집, 판정 초안을 만든다. 공개되는 '검토 완료' 판정은 사람이 승인한다.

- **기사 수집·본문 추출(시스템)**: URL에서 제목·부제·본문을 가져와 문장 단위로 나눔
- **제목-본문 일치 분석(시스템)**: 제목이 본문과 어긋나면 낚시성 의심 표시
- **검증 대상 주장 추출(시스템)**: 사실 여부를 따질 수 있는 주장만 골라냄
- **근거 수집·대조(시스템)**: 기존 팩트체크 DB 조회 → 뉴스·웹·공공통계 검색 → 근거마다 지지/반박 분류, 인용문이 실제 출처에 있는지 대조
- **판정 초안·근거 카드 생성(시스템)**: 근거가 약하거나 충돌하면 검토 대기열로 보냄
- **기사 제출·이의 제기(독자)**: 판정에 동의하지 않으면 근거를 붙여 이의 제기
- **[사람 승인] 판정 승인(검토자)**: 대기열의 판정 초안을 확인·수정·승인해야 '검토 완료'로 공개
- **[사람 승인] 이의 처리·출처 목록 관리(관리자)**: 이의 제기 결론, 신뢰 출처 목록 추가·제외

## 핵심 파트너(KEY PARTNERS)

근거가 되는 팩트체크·뉴스·통계 데이터를 주는 곳과, 판정을 확인하는 사람을 주는 곳이 필요하다.

- **팩트체크 기관**: 팩트체크 기사와 판정 제공 (IFCN 인증 국내 매체 등. SNU팩트체크는 2024년 8월 운영 중단, 기존 자료는 읽기 전용 [11])
- **뉴스 데이터 제공처**: 언론사 RSS·제휴, 한국언론진흥재단 빅카인즈
- **공공 데이터 제공처**: 통계청 KOSIS, 공공데이터포털 — 수치 주장 검증용
- **학습 데이터 제공처**: NIA AI Hub 「낚시성 기사 탐지 데이터」 [13]
- **기술 제공처**: LLM API 사업자, 검색 API 사업자, Google Fact Check Tools API [10]
- **검토 인력**: 대학 언론·미디어리터러시 교육기관, 제휴 언론사 기자

## 핵심 이네이블러(KEY ENABLERS)

판정이 LLM의 기억이 아니라 검색해 온 근거에서만 나오게 만드는 기술이 핵심이다.

- **생성형 LLM**: 주장 추출, 근거 요약, 판정 이유 서술 [1][2]
- **검색 증강 생성(RAG)**: 검색한 근거 문서 안에서만 답하도록 제한 [4]
- **웹·뉴스 검색 API**: 주장마다 근거 후보 수집 (SAFE 방식: 응답을 사실 단위로 쪼개 검색으로 하나씩 확인 [6])
- **팩트체크 조회 API**: Google Fact Check Tools API의 ClaimReview 검색 [10]
- **제목-본문 일치 분류 모델**: AI Hub 낚시성 기사 데이터로 학습 [13]
- **인용 검증 모듈**: 근거 카드의 인용문이 실제 출처 페이지에 있는지 문자열 대조 — AI 검색의 허위 링크·잘못된 인용 문제 대응 [9]
- **검토 워크플로우**: 검토 대기열, 판정 수정 이력, 이의 제기 처리

## 핵심 데이터(KEY DATA)

원천은 사용자 입력 기사, 학습용 공개 데이터, 근거용 팩트체크·뉴스·통계, 서비스가 만드는 검토 이력으로 나뉜다.

- **사용자 입력 기사**: URL/본문 텍스트, 요청할 때마다 / 기사 저작권 때문에 전문은 분석 후 저장하지 않고 링크와 짧은 인용만 보관
- **AI Hub 낚시성 기사 탐지 데이터(146번)**: JSON(제목·부제·본문·문장 정보, 낚시성 여부 라벨, 7개 분야) / 학습 586,741건·검증 73,348건(팀 보유본 라벨 파일 수 기준) / 2022년 1회 구축 / AI Hub 이용약관 범위에서만 사용 [13]
- **팩트체크 DB**: ClaimReview 구조화 데이터(주장, 판정, 검증 기관, URL) / 수시 갱신 [10]
- **뉴스 아카이브**: 빅카인즈 등 기사 메타데이터·본문 / 일 단위 / 언론사 저작권 → 링크·인용 위주
- **공공 통계**: KOSIS·공공데이터포털 API / 통계 공표 주기
- **신뢰 출처 목록**: 관리자가 정리 / 분기별 점검
- **검토·이의 제기 이력**: 서비스 내부 생성 / 실시간 / 검토자 계정 외 개인정보 수집 안 함, SNS 작성자 식별정보 저장 안 함
- **평가셋**: FEVER·AVeriTeC(영어) [5][14] 구조를 참고해 한국어 주장-근거-판정 평가셋을 팀이 따로 구축

## 핵심 장벽(KEY BARRIERS)

가장 큰 장벽은 한국어 근거 확보와 LLM이 내놓는 인용의 신뢰성이다.

- **근거 확보**: 국내 유일의 한국어 팩트체크 통합 DB였던 SNU팩트체크가 재원 문제로 운영 중단 [11], 막 터진 사건은 아직 근거 자체가 없음
- **LLM 인용 신뢰성**: AI 검색 8종이 뉴스 출처 질의 1,600건 중 60% 넘게 틀렸고, 없는 링크를 만들어 내기도 함 [9]
- **저작권·접근 권한**: 언론사 기사 수집·저장 제한, robots.txt 정책
- **사용자 신뢰·편향 시비**: 정치 기사 판정은 편향 공격을 받기 쉬움 (SNU팩트체크도 '좌편향' 공세를 받음 [11])
- **규제**: AI 기본법(2026.1.22 시행) — 생성형 AI 사용 사실 사전 고지, 결과물 표시 의무 [12]
- **평가 기준 부족**: 한국어 주장 검증 벤치마크가 거의 없음

## 부정적 영향(NEGATIVE IMPACTS)

AI 판정이 틀리면 독자가 맞는 기사까지 믿지 않게 될 수 있다. 위험마다 완화책을 둔다.

- **오판 → 참 기사 불신**: ChatGPT 팩트체크를 본 참가자는 AI가 거짓으로 잘못 표시한 참 헤드라인을 덜 믿었고, 전체 판별력은 나아지지 않았음 [7] → 완화: 근거가 약하면 판정 보류, 검토자 승인 전에는 '검토 중'으로만 표시, 점수 대신 근거를 앞세움
- **낙인**: 특정 언론사·기자에게 '가짜뉴스' 꼬리표 → 완화: 매체 단위 점수는 만들지 않고 주장 단위로만 판정, 이의 제기 창구 운영
- **AI 의존**: 독자가 스스로 판단하지 않음 → 완화: 결론보다 출처 카드를 먼저 보여주고 원문 링크를 열게 유도
- **악용**: 판정 화면 캡처를 정치 공격에 사용 → 완화: 판정 시점·모델 버전·검토 여부를 화면에 함께 표시
- **허위 인용**: LLM이 출처를 지어냄 [9] → 완화: 인용문이 원문에 없으면 근거 카드에서 제외
- **개인정보**: SNS 게시글 작성자 정보 노출 → 완화: 본문만 분석, 작성자 식별정보는 저장하지 않음

## 비용(COSTS)

운영비의 대부분은 기사마다 반복되는 LLM·검색 호출비와 검토자 인건비다.

- **LLM API 호출비**: 기사 1건에 주장 추출 + 주장별 판정으로 여러 번 호출, 같은 기사·주장은 캐시로 재사용해 줄임
- **검색 API 호출비**: 주장마다 검색 여러 건
- **검토자 인건비**: 사람 승인이 필요한 판정 수에 비례 (자동 사실 검증은 사람 평가보다 20배 넘게 저렴하다는 보고 [6] → 자동화로 초안, 사람은 승인만)
- **데이터 라이선스**: 뉴스 데이터 제휴·이용료
- **서버·DB 운영**: 판정 DB, 검토 이력 저장
- **모델 학습**: 제목-본문 일치 모델 학습용 GPU (초기 1회 + 주기적 재학습)

## 수익(REVENUES)

일반 독자는 무료로 쓰고, 검토 워크플로우와 판정 DB가 필요한 기관이 비용을 낸다.

- **일반 독자**: 무료(하루 분석 횟수 제한) — 호출비는 아래 기관 수익으로 충당
- **언론사·포털(B2B 구독)**: 검토 대기열·판정 DB·근거 카드 생성 도구
- **교육기관(라이선스)**: 미디어 리터러시 수업용 실습 도구
- **플랫폼(API 과금)**: 커뮤니티·SNS 플랫폼에 판정 API 제공
- **공익 재원**: 재단·정부 지원 사업 — 단, 재원이 끊기면 서비스가 멈춘 SNU팩트체크 사례 [11]처럼 한 곳에 의존하지 않도록 재원을 나눔
- **광고 없음**: 신뢰성 판정 서비스와 광고주 사이의 이해충돌을 피함
