# 09_데이터 폴더 규칙

데이터는 다섯 층으로 나눈다. 아래로 갈수록 가공된 것이고, 위층은 아래층을 보고 다시 만들 수 있어야 한다.

| 층 | 폴더 | 내용 | 고쳐도 되는가 | 저장소 |
|---|---|---|---|---|
| 등록부 | `catalog/` | `datasets.yaml`. 쓰는 데이터셋의 출처·이용 조건·수집 방식 | 예 (데이터를 쓰기 전에 먼저 등록) | 올림 |
| 원자료 | `raw/` | 받은 그대로의 파일과 API 응답 | 아니오 | 제외 |
| 중간 | `interim/` | 정제·결합 중간 결과 | 예 (언제든 다시 만듦) | 제외 |
| 최종 | `processed/` | 판정·평가에 쓰는 표, 정답셋, AutoRAG corpus·qa | 변환 코드로만 (정답셋은 사람이 작성) | 제외 |
| 표본 | `samples/` | 테스트·시연용 소량 표본. 기사 본문은 넣지 않는다 | 예 | 올림 |

## 원자료 경로

```text
09_데이터/raw/<출처>/<데이터셋ID>/<수집일 YYYY-MM-DD>/<파일>
```

| 출처 폴더 | 내용 | 데이터셋ID |
|---|---|---|
| `collected` | 언론사 정치 섹션 직접 수집 | `news_press` |
| `open_assembly` | 열린국회정보 Open API | `assembly_bills`, `assembly_votes` |
| `law_go_kr` | 국가법령정보 공동활용 Open API | `law_current`, `law_detc` |
| `data_go_kr` | 공공데이터포털 (정책브리핑 정책뉴스) | `policy_news` |
| `aihub` | AI Hub 낚시성 기사 탐지 데이터 | 원본이 커서 트라이톤 공모전 폴더에서 바로 읽는다 |

- 데이터셋ID는 `catalog/datasets.yaml`의 `id`와 같아야 한다.
- 같은 데이터를 다시 받으면 덮어쓰지 않고 수집일 폴더를 새로 만든다. 수집기는 이전 수집일 폴더를 보고 이미 받은 기사·본문은 건너뛴다.
- `raw/collect_log.txt`에 매일 수집 결과와 오류가 쌓인다.

## 중간·최종 파일 이름

```text
09_데이터/interim/<데이터셋ID>__<단계>.<확장자>        예: aihub_clickbait__PO_train.jsonl
09_데이터/processed/<용도>__<내용>.<확장자>            예: gold__claims_evidence.csv
```

## 지켜야 할 것

1. 등록부에 없는 데이터는 쓰지 않는다. 먼저 `datasets.yaml`에 적는다.
2. 원자료는 손으로 고치지 않는다. 고칠 일이 있으면 `10_구현/src/pipeline`의 코드로 한다.
3. 인증키는 `.env`에만 둔다. 코드와 원자료 파일 이름에 넣지 않는다.
4. 보고서에 쓰는 수치는 `processed/`의 표에서 나온 것만 쓰고, 어느 데이터셋에서 왔는지 적는다.
5. 법령·국회 자료를 서비스 화면에 보여줄 때는 출처를 표시한다.
